## Self-review notes / concerns

- **Plugin id vs. crate name mismatch (by design, per brief):** `gencore-plugin-pty`/`gencore-plugin-fs` are the Cargo package names, but the runtime plugin identifiers passed to `tauri::plugin::Builder::new(...)` are the shorter `gencore-pty`/`gencore-fs`. Real Tauri plugins conventionally name the crate `tauri-plugin-<id>` so the app-side `tauri-build` can auto-discover ACL manifests by stripping that prefix. Since our crates don't follow that prefix convention (intentionally, to avoid colliding with the official `tauri-plugin-fs`), a future "apps" wave wiring these into a Tauri app's `capabilities/*.json` may need to double check that permission/ACL auto-discovery still resolves correctly, or use `Builder::plugin(...)` registration paths that don't depend on the naming convention. Flagging for the apps wave, not a blocker here since no app consumes these plugins yet.
- Test executors use a small dependency-free `block_on` built on the now-stable `Waker::noop()` (Rust 1.85+) instead of pulling in `tokio`/`futures`, keeping `dev-dependencies` to just `serde_json`.
- `cargo build`/`test`/`clippy` auto-generated `permissions/autogenerated/**` and `permissions/schemas/schema.json` in each crate (standard Tauri plugin convention, checked into official plugin repos) — left in place.

## Fix (Critical review finding — plugin id / `CARGO_PKG_NAME` mismatch)

- `crates/gencore-plugin-pty/Cargo.toml`: `[package].name` → `gencore-pty`, `links` → `gencore-pty`. Folder path unchanged (`crates/gencore-plugin-pty`).
- `crates/gencore-plugin-fs/Cargo.toml`: `[package].name` → `gencore-fs`, `links` → `gencore-fs`. Folder path unchanged (`crates/gencore-plugin-fs`).

- `Cargo.toml` workspace `members` left as folder paths (`crates/gencore-plugin-pty`, `crates/gencore-plugin-fs`) — unchanged, per instructions.
