## Fix (Wave 4 critical/important findings, post-review)

- Root cause of the Terminal typecheck break: `packages/config-vite`'s internal
  relative imports used a literal `.ts` suffix (required for Node's native ESM
  loader when Vite loads `vite.config.ts` and externally resolves the
  workspace package to its `src/index.ts` source), which triggers TS5097 for
  any consumer whose tsconfig doesn't set `allowImportingTsExtensions`.
  Extensionless / `.js`-suffixed imports were tried and both fail
  `vite build`'s `ERR_MODULE_NOT_FOUND` — the `.ts` suffix is the only one that
  resolves correctly at build time.
- Fix: kept the `.ts` suffix imports (needed for `vite build` to work), and
  moved `allowImportingTsExtensions: true` out of the two ad-hoc per-package
  overrides and into `packages/config-typescript/tsconfig.vite-app.json`
  (shared by both `apps/terminal` and `apps/explorer`), so any current or
  future Vite app consuming `@gencore/config-vite` typechecks without
  duplicating the flag per app. `packages/config-vite/tsconfig.json` keeps its
  own explicit flag (it extends `base`, not `vite-app`, and directly contains
  the `.ts`-suffixed imports).
- Verified: `pnpm --filter @gencore/terminal typecheck`,
  `pnpm --filter @gencore/explorer typecheck`, and
  `pnpm --filter @gencore/config-vite typecheck` all pass. Confirmed
  `vite build` for both apps now gets past config loading/module resolution
  (previously failing); a separate, pre-existing esbuild legacy-target
  (`safari13`/`chrome105`) transpile failure remains and is out of scope for
  this fix.
